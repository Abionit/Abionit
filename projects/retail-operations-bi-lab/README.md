# Retail Operations BI Lab

Business intelligence and data engineering case study for a retail operation that needs reliable sales, inventory, customer, and fulfillment metrics.

## Business Problem

Retail teams often make decisions from separate spreadsheets: sales, customers, products, inventory, stores, and deliveries. When those sources are not connected, managers can see revenue but cannot easily explain what is driving margin pressure, stockouts, late deliveries, or customer concentration.

This project builds a clean analytical layer for that problem. The goal is to move from scattered operational data to a model that can support Power BI reporting, SQL analysis, and repeatable decision-making.

## Solution

- Generate realistic retail source data.
- Validate core data quality rules before modeling.
- Build a star schema with fact and dimension tables.
- Calculate sales, margin, inventory, fulfillment, and customer metrics.
- Export Power BI-ready CSV tables.
- Provide SQL queries and DAX measures for dashboard construction.
- Document the reasoning behind the model and business recommendations.

## What The Project Demonstrates

- Data modeling for BI.
- ETL logic with Python and pandas.
- SQL analysis for business questions.
- Power BI-ready semantic model design.
- DAX measures for revenue, margin, delivery, stockout, and customer KPIs.
- Data quality validation.
- Clear explanation of problem, logic, and business impact.

## Repository Layout

- `src/`: data generation and model build scripts.
- `data/sample/`: sample source files generated by the pipeline.
- `data/powerbi/`: Power BI-ready model tables generated by the pipeline.
- `sql/`: business analysis queries.
- `powerbi/`: DAX measures and report blueprint.
- `docs/`: business case, modeling notes, and review guide.
- `tests/`: validation checks.

## Run

```bash
pip install -r requirements.txt
python src/generate_data.py
python src/build_model.py
python -m unittest discover -s tests
```

The pipeline creates a Power BI-ready star schema under `data/powerbi/`.

## Business Questions Covered

- Which stores and product categories generate the most revenue?
- Where is margin under pressure?
- Which stores have stockout risk?
- Which delivery methods create late fulfillment risk?
- Which customer segments contribute the highest sales?
- Which products require pricing, inventory, or operational review?

## Power BI Usage

Import the CSV files from `data/powerbi/` into Power BI and create relationships using the keys described in `powerbi/report_blueprint.md`. Add the DAX measures from `powerbi/measures.dax`.

This project does not include a `.pbix` file because binary Power BI files are difficult to review in Git. The model tables, measures, and report blueprint are included so the dashboard can be rebuilt and reviewed transparently.

## Review Path

1. Read the business case in `docs/business_case.md`.
2. Review the model decisions in `docs/modeling_notes.md`.
3. Inspect the Power BI model blueprint in `powerbi/report_blueprint.md`.
4. Review the DAX measures in `powerbi/measures.dax`.
5. Run the pipeline and tests.
6. Import `data/powerbi/*.csv` into Power BI.
